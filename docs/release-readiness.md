# 对外发布验收

本清单区分“源码已公开”与“可以向大量用户承诺稳定”。0.2.0 beta 2 已同步到 [GitHub](https://github.com/muxin-maker/moqi)；跨平台和真实聊天验证仍需完成。

## 已在本地验证

- 单元及回归测试覆盖短 ID 兼容、哈希碰撞、并发写入、损坏数据保护、歧义纠正、误命中和用户反馈。
- MCP 端到端测试完成握手与八个工具调用，包括冲突语境和删除测试记录。
- wheel 构建后在隔离虚拟环境安装，并走通 `guess → correct → scan`。
- `research` 的未配置路径、结果结构和输入校验已在本地测试；Brave Search API 的真实请求仍需有密钥的环境验证。

## 大范围推广前的阻断项

1. 让 `.github/workflows/ci.yml` 在 Windows 和 Linux 全部通过；本地测试不能代替这一步。
2. 在至少两种实际 MCP 宿主里，按 README 从干净环境安装，确认配置、工具发现、中文输出和错误提示都可用。
3. 征得参与者同意，用真实聊天连续测试。建议至少记录 50 条“本应召回”的消息与 50 条“相似但不应套用”的消息；人工核对 `usable=true` 的含义是否正确、弱匹配是否只作提示、模型是否主动调用工具。未达到可接受的误用率前不要宣传“不会再犯同样的错”。
4. 每版审查待推送文件、作者邮箱、设计文档以及示例，确认没有不想公开的个人信息或真实默契数据。不要把 `~/.moqi/`、`.tmptest/`、`.venv/` 发布出去。
5. 明确项目主页、维护者、问题反馈渠道和包名所有权，再决定是否发布到 PyPI。发布后用干净机器执行 README 的安装步骤。

## 已知产品边界

- MCP 宿主是否调用工具不受本包强制控制。
- 文字匹配不会理解反讽、图像或所有圈内变体；低分结果需要当前对话确认。
- 本地 JSONL 可读可搬，但 MCP 返回会进入宿主模型的上下文。使用云端模型时应视为向该服务提供了所返回的记录。
- 当前没有跨设备同步、多用户隔离或自动从聊天中提炼记录。
- `research` 需要单独的 Brave Search API 密钥；搜索摘要只能提供候选线索，不能证明某个梗的最早出处。
